## What We Are Building

A complete ROS2-based software architecture for a mobile manipulation robot system consisting of:
- **AGV (Automated Guided Vehicle)**: Mobile base with navigation capabilities
- **Robot Arm**: 6-DOF manipulator for pick-and-place operations
- **Ultrasound Sensors**: Proximity detection and obstacle avoidance
- **Camera**: Vision-based object detection and pose estimation

The architecture follows a layered design pattern:
1. **Hardware Abstraction Layer (HAL)**: Abstract interfaces for hardware devices
2. **Driver Layer**: Concrete implementations (EtherCAT for arm, CAN for AGV)
3. **Control Layer**: Real-time trajectory execution and servo control
4. **Planning Layer**: Motion planning using MoveIt2 and Nav2
5. **Capability Layer**: High-level abstractions hiding hardware details
6. **Perception Layer**: Vision processing and sensor fusion
7. **Task Manager**: Task scheduling and execution management

## Decisions Made

- **Header-only common library** — reason: Simple types and utilities don't need compilation
- **Interface-based HAL design** — reason: Allows swapping hardware implementations without changing upper layers
- **Capability layer between Planning and Control** — reason: Provides high-level API that hides complexity
- **MoveIt2 for arm planning** — reason: Industry standard, well-tested motion planning
- **Nav2 for AGV navigation** — reason: ROS2 standard navigation stack
- **Behavior trees for task management** — reason: Flexible, visual, industry-proven for robotics tasks
- **EtherCAT for arm driver example** — reason: Common in industrial robots, real-time capable
- **CAN for AGV driver example** — reason: Standard for mobile robots, simple protocol
